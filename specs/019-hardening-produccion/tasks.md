## Format: `[ID] [P?] [Story?] Description`

- `[P]`: puede ejecutarse en paralelo solo si sus dependencias están completas y no toca los mismos archivos.
- `[US1]`…`[US6]`: historia trazable de `spec.md`.
- Cada tarea es una unidad cerrable: una implementación posterior debe ejecutar exactamente una tarea por pase, su `Verify` debe salir 0 y solo entonces puede marcarse `[x]`. Excepción terminal: el cambio `[ ]→[x]` de T120 viaja en el único `handoffSha` junto al recibo permitido y se valida después de ese commit; T121 se cierra análogamente en `rolloutReceiptSha` con solo recibo/summary derivado y su checkbox. Ninguno es autoridad de despliegue.
- Las tareas RED usan `scripts/testing/expect-red.mjs`, que sale 0 únicamente cuando fallan las pruebas nombradas por la razón funcional esperada y no hay fallos de infraestructura.
- Toda tarea RED que importa un módulo/CLI aún inexistente DEBE crear en esa misma tarea un scaffold mínimo cargable con la firma pública prevista y un código funcional `*_NOT_IMPLEMENTED` que contenga el marcador esperado. `MODULE_NOT_FOUND`, import error, colección vacía o fallo de setup nunca cuentan como RED válido; los scaffolds de tareas `[P]` deben vivir en archivos disjuntos.
- Los nombres de migración reservan timestamps SDD019. Al implementarlas se debe ejecutar primero `cd packages/database && supabase migration new <suffix>` y normalizar el archivo generado al path exacto indicado antes de editarlo.
- Desde T003 existe el inventario baseline y toda tarea que cree/reemplace una rutina (`T013`, `T026`, `T042`, `T058`, `T077`) actualiza la clasificación y ejecuta `privileged-operations-inventory.mjs --assert-complete`; ningún conteo fijo sustituye la igualdad exacta con catálogo/ACL/triggers/policies. T112 no puede cambiar firma/definición/search path: aplica solo revokes versionados, refresca `grantFingerprint` mediante el manifiesto de revokes esperado y exige que el diff no contenga otra clase de cambio.
- El comando `Verify` de cada tarea no-RED es su aserción focal y se concatena obligatoriamente con el gate del tipo de cambio: web/frontend → `pnpm typecheck:web && pnpm test:web && pnpm --filter web lint && pnpm format:check && pnpm build:web`; fuente o salidas de contratos → además `pnpm contracts:generate` y diff generado limpio; API → `pnpm test:api`; migración → `pnpm verify:migrations`. Una tarea RED es la única excepción temporal: cierra cuando `expect-red` devuelve 0 por la razón funcional exacta, pasan format/lint/typecheck/build que no ejecutan ese test y no existe otro fallo; el gate verde que incluye la prueba nueva es obligatorio en su tarea GREEN pareada y en el story gate. Nunca se marca una RED si falla por infraestructura o por una regresión ajena.

- Keep new writers behind kill switches; deploy schema/readers first.
